# 01 - Consistent, sanitized failure messages

**What to build:** A failed CSV Viewer action shows the same deliberate user message on desktop and web. Unexpected defects show a generic message. Desktop errors, including dropped-file failures, contain no Electron invocation prefix. Diagnostics distinguish expected failures, defects, interruption, and cleanup failures without exposing CSV data or local paths.

**Blocked by:** Effect workspace adoption ticket 04 - Consolidate Working CSV coordination and observe every request. It establishes the shared entry adapter for all CsvViewer requests.

- [ ] Before changing error handling or transport, use the CSV Viewer verification skill to reproduce the desktop prefix by renaming a column to a blank name. Record the current desktop and web messages.
- [ ] Represent deliberate workspace validation failures with `Data.TaggedError`. Cover lifecycle and lookup checks, edit validation, unknown CSV columns, missing CSV rows, and unavailable undo or redo. Reuse tags where recovery and diagnostic handling are the same. Broken invariants remain defects.
- [ ] Keep `DataEngineError` and `CsvSourceUnavailableError` as their existing classes with sanitized messages. Recognize them by `instanceof`; do not add tags solely for consistency. Use the installed Effect release, `4.0.0-rc.115`, as the API authority.
- [ ] At synchronous and Promise adapters into Effect, convert recognized expected errors into typed failures and preserve unexpected exceptions as defects before stages record diagnostics. Native Effect code fails explicitly for expected conditions. Throwing a tagged error inside `Effect.sync`, rejecting inside `Effect.promise`, or using default `Effect.tryPromise` must not misclassify or obscure an expected error.
- [ ] Translate failures once in the shared entry adapter, inspecting `Exit` and `Cause` before squashing them or constructing the public rejection. A single recognized expected failure retains its message. Defects, interruption, and multiple causes, including an `AggregateError`, reject with `The CSV workspace could not complete the request.`. A recognized tag on a defect does not make it an expected failure.
- [ ] Preserve declared outcomes such as `failed`, `rejected`, and `invalid-key`, existing deliberate validation messages, and public request, result, and event shapes. Existing request-contract assertions remain unchanged in this slice; ticket 02 replaces the unsupported-operation rejection when decoding is introduced.
- [ ] Keep failure, defect, and interruption classification based on Effect's cause kinds. Use domain tags and existing error classes for further classification. Preserve `ComparisonCleanupError` handling and report cleanup status separately from the product outcome. Retain original causes internally through classification and cleanup.
- [ ] Emit only allowlisted diagnostic identifiers, stage names, timings, and normalized outcomes. Do not log or trace raw causes, error messages or stacks, request payloads, CSV values, column names, source names or paths, SQL, or driver details.
- [ ] Make both desktop request and dropped-source IPC handlers return success or sanitized failure values. The preload returns the success value or throws a new Error with the sanitized message. The request handler uses the shared entry adapter's translated message; the transport does not send error objects or nested causes.
- [ ] Sanitize dropped-source failures before constructing the IPC response because this channel calls the desktop host directly. Preserve absolute-path validation and the existing unsupported-file and directory messages as recognized expected failures. Normalize expected filesystem failures from file inspection and identity lookup into `CsvSourceUnavailableError`. Unexpected failures use the generic workspace message. Do not classify errors by message text or forward arbitrary error messages.
- [ ] Extend shared contracts against native DuckDB and DuckDB-Wasm with an expected synchronous validation failure and an expected Promise rejection through real requests. Assert their existing messages and `recoverable-failure` diagnostics. Keep existing interruption and cleanup-failure assertions.
- [ ] Force a defect through a real request with sentinel SQL and a local path in the error and its nested cause. Assert the generic public message, `defect` classification, and absence of the sentinels from the rejection and captured diagnostics. Use an existing injection seam if it can preserve the defect; otherwise add only the seam needed for this case.
- [ ] Verify with a fake IPC pair that an expected request rejection and an expected dropped-source rejection reach the renderer with sanitized messages and no Electron prefix. Cover a missing or inaccessible dropped file and an injected unexpected failure without exposing sentinel paths or internal error text.
- [ ] Use the verification skill to confirm matching desktop and web messages for a blank column rename and one Comparison action. Run the required type, lint, and test checks and both builds. Effect must remain absent from the desktop renderer bundle.
